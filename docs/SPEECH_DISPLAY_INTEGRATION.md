## 1. 当前可运行链路

```text
MockAudioRecorder -> EvidenceStore / AudioReference
  -> MockASRProvider -> TranscriptResult
  -> SpeechInputService -> TeamGateway.submit_transcript()
  -> UserInput -> TeamGateway.next_input()

调用方提供固定测试回答
  -> SpeechOutputService -> MockTTSProvider -> AudioReference
  -> MockAudioPlayer -> PlaybackState(completed)
```

入口为 `speech/demo.py`，运行：

```bash
uv run python -m speech.demo
```

成功时显示模拟输入交接、模拟播放完成，以及录音完成、ASR、TTS、播放各 1 次和资源释放。输入队列读取仅用于这个独立演示进程，不得复制到已有教学消费者旁边竞争读取。

演示不打开真实麦克风或扬声器、不联网、不提交机器人动作、不消费 Runtime 事件。固定回复由示例调用方提供；它不是教学回答生成器。TTS 产生 WAV 测试音调，播放器按音频时长模拟播放。

入口用 `AsyncExitStack` 在异常或退出时分别关闭输入、输出、Runtime 和模拟感知。示例中的 `gateway.cancel_task()` 只取消核心任务；它不替代语音服务的关闭。

## 2. 装配和所有权

| 对象 | 创建与持有方 | 交接约束 |
| --- | --- | --- |
| EvidenceStore | 应用装配方 | 录音、TTS、播放器使用同一存储；只传证据编号，不传本地路径 |
| AudioDeviceLease | 语音层定义，应用装配方创建 | 同一组录音器、播放器必须注入同一个实例；独立默认实例不能互斥 |
| SpeechInputService | 应用装配方 | 拥有录音器和 ASR 作业，必须关闭；不拥有核心任务取消职责 |
| SpeechOutputService | 应用装配方 | 拥有合成作业和播放器，必须关闭；不持有任务或动作归属映射 |
| TeamGateway | 核心装配方 | 保留最终输入校验、录音去重、输入编号生成和迟到输入拒绝 |

设备占用由录音器和播放器取得，仅由原拥有者释放。合成与识别等待本身不占用设备。合成可以在录音时完成，但其后的播放会因设备占用失败；不自动排队，也不打断录音。是否推迟整次播报由核心调度决定。

本轮集成用例确认：关闭已完成的录音服务不会误释放正在播放的租约；关闭已完成的输出服务也不会误释放随后开始录音的租约。互斥仍限于单进程、同一 asyncio 事件循环的模拟适配器。

## 3. 已验证行为

新增 `tests/test_speech_integration.py`，覆盖以下 6 项：

1. 连续两轮录音到核心输入，再播放固定回答；并发 finish 每轮只生成一个输入，检查录音、ASR、TTS、播放调用次数。
2. 录音期间请求输出，播放明确失败且录音保持活动；结束录音后可用新播放编号重试。
3. 播放期间拒绝录音；确认 stopped 后可开始录音并完成识别。
4. 关闭旧输入服务时，当前播放继续持有租约；关闭输出后确认停止及释放。
5. 关闭旧输出服务时，当前录音继续持有租约；取消录音后确认释放。
6. ASR 与 TTS 同时等待时，显式关闭两个服务；释放模拟响应门后无迟到输入、无播放、无后台任务。

全部用例在测试兜底清理之前检查资源释放。既有输入、输出测试继续覆盖空识别、非 final、失败、超时、迟到转写拒绝、合成取消、播放取消、停止失败和外部等待取消。

原独立分支检查结果（不是同步当前 main 后的结果）：`uv run ruff check .` 通过；`uv run ruff format --check .` 通过（59 个文件）；`uv run basedpyright` 为 0 错误、0 警告；`uv run python -m unittest discover -s tests -v` 全部 74 项通过。模拟演示运行成功。前端未修改，本轮未重复执行 Flutter 检查。

当前有 `runtime/events.py` 中的 ActionEventHub 单点消费并广播，具体生命周期由应用装配；独立演示和测试另有隔离消费者。本轮没有新增 `ActionManager.next_event()` 消费者。页面后续只订阅核心提供的事件广播接口，不直接读取 Runtime 队列。

核心合同审查还需处理既有差异：MODULE_CONTRACT 的播放器表仍写 `PlaybackResult` 和结构化 `ResourceError`，现有 Protocol 返回 `PlaybackState`，其 `error` 为 `str | None`。应明确内部模型到网络资源的转换，不创建平行播放状态体系。

## 5. 页面适配交接

当前 Flutter 的 `ClassroomService` 和 `SessionModel` 是页面内部数据源与视图模型，不能当成 HTTP DTO。核心接口就绪后，由语音与展示负责人实现前端网络适配，Widget 保持通过控制器访问服务。

需要实际转换的差异包括：模拟消息编号是整数，合同中的 message_id 是不透明字符串；模拟事件提供整份页面状态，草案 SSE 是按资源类型发送 payload；当前图片为打包示例资源，真实图片须按证据 content_url 获取。不能直接用模拟消息或事件解析方式读取真实后端。

联调顺序为：系统能力和实例识别、任务快照、创建任务与文字输入、停止确认、事件恢复、录音状态与媒体展示。具体端点采用审核后的合同，不提前填入 `api_paths.dart`。

必须验证：请求失败保留输入；断线明确提示；重连先恢复快照并衔接事件；重复事件不重复追加消息；后端实例改变时清理旧引用且不重放控制命令；录音转写由后端提交，前端不重复 POST 文本；202 只表示请求已接受，不能显示为设备已停止。
