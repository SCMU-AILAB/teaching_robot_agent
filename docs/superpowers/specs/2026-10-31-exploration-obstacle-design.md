# 自由探索与深度避障设计

日期：2026-10-31。状态：待项目负责人审核。

## 1. 目标

孩子说“去探索一下吧”，机器人在房间里自己走：
- 边走边避开障碍；
- 每走一段停下看一眼，发现之前没讲过的东西就讲一句（有安全资料的优先）；
- 结束时一句话总结。

范围上限：离起点 3 米以内，最多 5 分钟。任何时候孩子说话、前端点停止，都先停车。

避障同时作用于平时的前进指令：“往前走两米”途中遇到障碍也会停车，并报告“前方有障碍物”。

已确认的取舍：
- 走法由确定的程序决定，大模型只负责说什么，不决定往哪走。
- 车身高约 0.3 米、宽 0.25 米（负责人实测）。

第一版不做：
- 横移绕障（横移未标定）；
- 建图；
- 自动回到起点；
- 前端的“探索中”状态显示。

## 2. 硬件与已验证事实

- RealSense D435i 深度节点（2026-10-31 实测为 `/dev/video0`）可经 V4L2 直接读取 Z16 格式，不需要 librealsense 或 sudo。实测参数：
  - 用 `linuxpy` 读取，640×480 约 24 帧/秒；
  - 有效像素 76%；
  - 单位为毫米。
- OpenCV 打不开 Z16 节点，所以深度读取不能复用 `UsbCamera`。彩色画面仍由 `/dev/video4` 经 OpenCV 读取，两个节点可以同时打开。
- 深度相机约 0.3 米以内读不出距离（读数为 0）。
- 摄像头略朝上，车前近处地面落在视野外，贴地矮小物体存在盲区。盲区距离由标定工具测出并写入文档。
- 摄像头只朝前，后退时看不到后面。

## 3. 模块

### 3.1 深度读取 `perception/depth/`

- **`DepthCamera`**：后台线程以 V4L2 读取 Z16，只保留最新一帧及其采集时间。`start()`/`close()` 管理生命周期，模块导入时不打开设备。
  - 设备自动查找：在 `/sys/class/video4linux` 中找名称含 RealSense、且支持 Z16 的节点；`DEPTH_DEVICE` 可指定路径。
- **`clearance(frame, mount, body)`**：纯函数，输入一帧深度，输出 5 个方向的前方空隙（米）。
  - 内参默认取 D435 640×480 深度的典型值（fx=fy=383，cx=320，cy=240），可由环境变量覆盖。
  - 按摄像头安装高度与俯仰角，把像素换算到车体坐标。只保留车身高度范围内的点（离地 0.03 米至车高 0.3 米），地面与高过车身的物体（如桌面下沿以上）不算障碍。
  - 视野约 ±43°，分为 5 个方向扇区。
  - 另算“正前方通道”的空隙：通道宽度为车宽 0.25 米加两侧各 0.075 米余量，共约 0.4 米。
  - 每个扇区或通道取障碍点前向距离的第 5 百分位，点数少于阈值（默认 50）视为无障碍。
  - 返回的结构带采集时间，供调用方判断是否过期。
- **`app/depth_calibrate.py`**：车放在空地上运行。
  - 拟合地面平面，输出摄像头离地高度与俯仰角，以及车前最近可见地面距离（即盲区）。
  - 输出 `DEPTH_CAMERA_HEIGHT_M`、`DEPTH_CAMERA_PITCH_DEG` 供写入 `robot.env`。
  - 地面点不足时报错，说明原因。

### 3.2 避障守护 `robot/obstacle_guard.py`

`GuardedRobotAdapter(RobotAdapter)` 包在底盘适配器外层，其余接口原样转发。
- **前进**（`move_relative` 距离为正）：在子任务中执行内层前进，同时每 0.1 秒检查一次正前方通道空隙。满足以下任一条件，就取消内层前进，由内层负责发停车帧并确认静止，再抛出 `ObstacleError("前方有障碍物")`：
  - 空隙小于 `OBSTACLE_STOP_M`（默认 0.4）加上当前速度下的滑行量；
  - 深度数据超过 0.5 秒未更新（报“看不清前方”）；
  - 上一次空隙小于 0.6 米、本次通道内有效点骤减（贴近到读不出距离）。
- **启动前检查**：开始前进前空隙已不足，直接拒绝，不发运动指令。
- **后退**：单次限制 0.3 米，超出时参数校验失败。
- **转向**：原地转向不检查前方空隙，由底盘自身的堵转与超时保护兜底。
- **深度相机未配置**（`DEPTH_CAMERA=off`）：不包装，行为与现在相同（模拟底盘与现有测试不受影响）。真车配置了深度相机时，所有前进都经过守护。

`MoveRelativeSkill` 遇到 `ObstacleError` 时，动作记为 failed，failure 文本为“前方有障碍物，已停下”。宿主现有的失败处理（作废本轮、可继续对话）不变，回答文案带上失败原因。

### 3.3 探索控制器 `agent/exploration.py`

`ExplorationController` 按任务创建，只通过 `TeamGateway` 的公开方法工作：提交与等待动作、观察、读取快照和资料库。

主循环：
1. 记录起点位姿。先观察一次，有新物体就讲解。
2. 读取 5 个扇区的空隙，为每个候选方向打分：
   - 空隙按 1.5 米封顶计入；
   - 按 0.5 米网格记录走过的格子，没去过的格子加分；
   - 走完这一段会超出离起点 `EXPLORE_RADIUS_M`（默认 3）的方向排除。
3. 可选方向的空隙不足 `0.4 + 0.15` 米时，原地转 90°（交替方向，靠近边界时优先朝起点方向）再看。累计转满 360° 仍无可走方向，就结束探索。
4. 先 `turn_relative` 转到所选方向，再 `move_relative` 前进 `min(0.5, 空隙 − 0.4)` 米，速度 0.15 米/秒，前进经过 3.2 的守护。
5. 停下观察，更新已见物体。物体名称规范化后，互相包含的视为同一个，例如“椅子”与“蓝色椅子”。
6. 有新物体时生成一句讲解并提交 `speak`，等待播报结束。
   - 讲解直接调用大模型，不经过 `EmbodiedAgent` 的工具循环。输入为新物体与方位，以及资料库按物体检索到的条目（最多 3 条）。
   - 要求一句话、30 字左右，有安全条目时给提醒，并遵守系统提示里关于观察依据和不保证安全的规则。
   - 资料库有条目的物体优先，每次最多提两个。
7. 满足以下任一条件时结束，并播一句总结：
   - 到 `EXPLORE_MAX_S`（默认 300 秒）；
   - 无路可走；
   - 动作连续失败 3 次；
   - 观察或讲解连续出错 3 次。

触发与打断：
- `ToolAdapter` 新增工具 `start_exploration()`，没有参数，范围与时长取配置。只有同时具备前进、转向、定位能力并配置了深度守护时，才注册这个工具。
- 模型调用后，工具立即返回“已开始”。本条消息以模型的文字回答作答，例如“好的，我开始探索啦”。
- `RobotHost` 维护每个任务的探索后台作业：
  - 新输入进入 `handle` 时，先取消探索并等待其动作停止确认，再处理输入；
  - `cancel` 与 `close` 同样先停探索；
  - 探索作业的异常只记日志并结束探索，不影响任务；
  - 停车无法确认导致执行层锁定时，任务结束。
- 探索中的转向、前进、观察、播报都是普通动作和观察事件，前端照常显示。注意：现有服务只在处理用户消息期间把播报记成机器人消息，探索在后台进行时讲解只以 `speak` 动作出现（文字在动作参数 `text` 中），不进入聊天消息列表。

## 4. 配置（`robot.env`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `DEPTH_CAMERA` | `off` | `realsense` 启用深度守护与探索 |
| `DEPTH_DEVICE` | 自动查找 | 深度节点路径 |
| `DEPTH_CAMERA_HEIGHT_M` | 必填（启用时） | 标定工具输出 |
| `DEPTH_CAMERA_PITCH_DEG` | 必填（启用时） | 标定工具输出，朝上为正 |
| `ROBOT_BODY_HEIGHT_M` | 0.3 | 车高 |
| `ROBOT_BODY_WIDTH_M` | 0.25 | 车宽 |
| `OBSTACLE_STOP_M` | 0.4 | 停车距离（不含滑行量） |
| `EXPLORE_RADIUS_M` | 3 | 离起点最远距离 |
| `EXPLORE_MAX_S` | 300 | 单次探索最长时间 |

新增依赖 `linuxpy`，放入新的可选依赖组 `depth`。Jetson 启动命令追加 `--extra depth`。

## 5. 出错处理

| 情况 | 处理 |
|---|---|
| 深度相机打不开或中断 | 前进全部拒绝；探索不启动或立即结束，并播一句“我看不清前面，先停下了” |
| 单个动作失败（遇障、转向未到位） | 探索换方向继续；连续 3 次结束 |
| 停车无法确认 | 执行层锁定、任务结束（现有规则） |
| 视觉或大模型出错 | 这一站跳过讲解；连续 3 次结束 |
| 孩子插话、前端停止 | 先停探索与当前动作，确认停车后再处理 |
| 后端重启 | 探索不恢复，里程计从 0 开始 |

## 6. 测试

单元测试，不依赖真实设备：
- **`clearance`**（合成深度图）：
  - 地面点被排除；
  - 车身高度以上的点被排除；
  - 通道内外区分正确；
  - 第 5 百分位抗零星噪点；
  - 点数阈值生效；
  - 俯仰角换算正确。
- **避障守护**（模拟底盘 + 可控假深度源）：
  - 前进途中出现障碍时停车并抛出 `ObstacleError`，车停在障碍前；
  - 启动前已有障碍时拒绝前进；
  - 深度中断时停车；
  - 贴近障碍后读数消失时停车；
  - 后退超过 0.3 米被拒绝；
  - 未配置深度时行为不变；
  - 经 Runtime 执行的技能记为 failed，并带上原因。
- **探索控制器**（模拟底盘 + 假深度 + 假视觉 + 假模型）：
  - 位置不超出半径；
  - 走不通时转向，转满一圈后结束；
  - 新物体只讲一次，名称变体视为同一物体；
  - 有资料的物体优先讲；
  - 到时间结束；
  - 连续失败结束；
  - 插话时先停探索再回答；
  - 任务停止时停车；
  - 探索中执行层锁定时任务结束。

真机验收（负责人在车旁）：
1. 运行标定工具，记录高度、俯仰角与盲区。
2. 车前约 1 米处放纸箱，说“往前走一米”，车应在纸箱前约 0.4 米处停下，并说明前方有障碍。
3. 在 3 米范围内探索 2 分钟：无碰撞；讲解的物体与画面一致；不超出范围；说话能打断。
