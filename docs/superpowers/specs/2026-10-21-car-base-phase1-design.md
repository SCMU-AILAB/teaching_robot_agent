# 麦克纳姆轮底盘阶段 1：开环运动与串口协议设计

日期：2026-10-21。状态：项目负责人已口头确认三段设计，书面稿待审阅。

## 1. 目标与范围

小车为 MINDA-01 四路电机驱动板（STM32F407VET6）加四个麦克纳姆轮。阶段 1 目标：Jetson 或 Mac 通过串口让小车前后、左右平移和原地旋转，并具备看门狗停车。

分两阶段：

- **阶段 1（本文）**：开环。主机发送归一化速度 `vx, vy, wz`（千分比），固件按麦克纳姆运动学换算为四轮 PWM 占空比；编码器只上报不参与控制；提供单电机测试命令用于标定轮位与方向。
- **阶段 2（另行设计）**：测量编码器每圈脉冲、轮半径和轮距，改为 PID 轮速闭环，指令使用物理单位（mm/s、mrad/s），接入 QMI8658 航向，再实现 Python `RobotAdapter` 接入现有 Runtime。

阶段 1 不做：PID、IMU、`RobotAdapter`、Jetson 部署、HTTP 接口。

成功标准：

1. Rust `car-core` 与 Python 协议实现通过同一组测试向量；Rust `fmt`/`clippy -D warnings`/`test` 与 Python 四项检查通过。
2. 架空测试：`--motor` 逐个确认轮位和方向并填入常量表；`V` 指令下四轮转向符合运动学。
3. 落地低速测试：前后、左右平移、旋转方向正确；拔掉 USB 线 300 ms 内停车。

## 2. 硬件事实（由原固件反汇编和模拟执行得到，待原理图核对）

时钟：原固件使用 HSE（PLLM=8，PLLN=168，PLLQ=4，PLLP 未能确定），晶振频率无法从板面确认。阶段 1 固件改用 HSI 16 MHz 经 PLL（M=16，N=336，P=2，Q=7）得到 168 MHz，不依赖外部晶振。

| 电机 | 正转 PWM | 反转 PWM | 编码器 | 原固件编码器方向 |
| --- | --- | --- | --- | --- |
| M1 | TIM1 CH3 PE13 | TIM1 CH4 PE14 | TIM5 PA0/PA1 | -1 |
| M2 | TIM1 CH1 PE9 | TIM1 CH2 PE11 | TIM2 PA15/PB3 | -1 |
| M3 | TIM9 CH1 PE5 | TIM9 CH2 PE6 | TIM4 PB6/PB7 | +1 |
| M4 | TIM11 CH1 PB9 | TIM10 CH1 PB8 | TIM3 PB4/PB5 | +1 |

- PWM 10 kHz（ARR=16799，PSC=0），PWM 模式 1。原固件采用快衰减（正转引脚输出占空比、反转引脚为 0）；实测该方式死区约 50%（48% 不转、52% 起转，电池 12.5 V）。阶段 1 改为慢衰减：正转时正转引脚全开、反转引脚输出 (1−占空比) 的反相 PWM，反转相反，零时两路均为 0。慢衰减下 15% 即可起转，转速与占空比近似线性。
- 编码器为正交编码器模式（SMS=3，输入滤波 4）。TIM2、TIM5 为 32 位，TIM3、TIM4 为 16 位。
- 串口：USART1 PA9/PA10（板上 UART1 口，带一键下载电路：DTR→BOOT0，RTS→复位）、USART2 PD5/PD6、USART3 PD8/PD9，均 115200 8N1。板上 UART2 口对应 USART2 或 USART3，另一路推测接无线模块。
- LED：PE10。有源蜂鸣器：PA8（高电平响）。IMU：QMI8658，I2C2 PB10/PB11。
- 轮位标定（2026-10-21 架空实测）：左前 M4、右前 M1、左后 M3、右后 M2；四个电机正转时轮子均向前转，正转时编码器计数（按上表方向修正后）均为正。

## 3. 通信链路

- UART1 用于烧录和调试日志，也可作为开发时的通信口；正式通信使用板上 UART2 口。
- 固件启动时在 USART1、USART2、USART3 都发送开机帧 `$B` 并同时监听；第一条通过校验的命令帧所在端口被锁定为通信口，此后只处理该口的命令、只向该口发送应答和遥测，其余端口被忽略。锁定前不发送遥测。锁定结果经 USART1 调试日志输出。开发时可只接 UART1 一根线完成烧录、命令和日志；正式部署仍建议使用 UART2 口，避免误触发一键下载电路。
- 主机打开串口前必须将 DTR、RTS 置低，避免经 UART1 误复位或进入引导程序。

## 4. 串口协议

### 4.1 帧格式

`$<命令>,<字段>,...*<校验>\n`

- 校验：`$` 与 `*` 之间（不含二者）所有字节的 CRC-8，多项式 0x07，初值 0x00，不反射，无异或输出；写成两位大写十六进制。
- 字段均为十进制整数，可带负号。
- 小车接收的命令帧（含 `$`、`*`、校验和换行）最长 64 字节；超长、缺少 `*`、校验错误或字段不是整数时整帧丢弃并回复错误帧。小车发出的帧最长 96 字节（遥测最坏约 88 字节），主机解析上限为 128 字节。
- 接收端忽略 `\r`；`$` 之前的字节丢弃（用于从噪声中重新同步）。

### 4.2 主机 → 小车

| 命令 | 格式 | 字段与范围 |
| --- | --- | --- |
| 速度 | `$V,seq,vx,vy,wz` | 均为千分比 -1000..=1000；vx 正为前进，vy 正为向左平移，wz 正为逆时针 |
| 单电机 | `$M,seq,motor,duty` | motor 1..=4；duty 千分比 -1000..=1000 |
| 停止 | `$S,seq` | 立即停车 |
| 心跳 | `$P,seq` | 只回复应答，不刷新运动看门狗 |

`seq` 为 0..=65535 循环序号。

### 4.3 小车 → 主机

| 帧 | 格式 | 说明 |
| --- | --- | --- |
| 应答 | `$A,seq,code` | 每条可解析的命令回复一次；code：0 成功，2 参数越界，3 未知命令，4 字段数量错误 |
| 错误 | `$E,reason` | 无法取得可靠 seq 时发送；reason：1 校验错误，2 超长，3 格式错误 |
| 遥测 | `$T,ms,state,e1,e2,e3,e4,d1,d2,d3,d4` | 20 Hz；ms 为开机毫秒（u32 循环）；state 0 停止、1 运动、2 看门狗停车；e 为编码器累计计数（i32）；d 为实际输出占空千分比 |
| 开机 | `$B,version,port` | version 为整数固件版本（阶段 1 为 1）；port 为 1、2 或 3，表示发送该帧的 USART 编号 |

### 4.4 看门狗与运动状态

- 只有 `V`、`M` 刷新看门狗；超过 300 ms 无新运动指令时目标速度置零，状态变为 2，直到下一条运动指令。
- `S` 立即将目标与输出都置零，状态变为 0。
- `M` 期间其余电机输出为零；收到 `V` 后退出单电机模式。
- 输出斜率限制：每 10 ms 控制周期每轮占空比变化不超过 20 千分比（约 0.2 s 从 0 到 400 的上限）。看门狗触发后的减速同样受斜率限制；`S` 不受限制，立即归零。

## 5. 麦克纳姆运动学（阶段 1，归一化）

```
左前 = vx - vy - wz      右前 = vx + vy + wz
左后 = vx + vy - wz      右后 = vx - vy + wz
```

- 若任一轮绝对值超过 1000，四轮按同一比例缩放至最大值为 1000，保持运动方向。
- 结果乘以占空上限 400/1000（即最大 40% 占空比）后输出。
- 轮位到电机号的映射及每个电机的方向符号存为固件常量表，标定前使用占位值，标定后更新。

## 6. 代码结构

### 6.1 `firmware/car-core`（纯逻辑，`no_std`，主机可测）

- `crc8`、帧解析（`parse_frame`）与编码（应答、错误、遥测、开机帧格式化到固定缓冲区）。
- `Command` 枚举：`Velocity { seq, vx, vy, wz }`、`Motor { seq, motor, duty }`、`Stop { seq }`、`Ping { seq }`。
- `mix_mecanum(vx, vy, wz) -> [i16; 4]`（按轮位，含等比缩放与占空上限）。
- `MotionState`：接收命令与当前时间（毫秒），输出每周期目标占空比；包含看门狗、斜率限制与状态码。
- `LineAssembler`：按字节累积一行，处理重同步与超长。

### 6.2 `firmware/car`（板级）

- 时钟配置为 168 MHz；PWM：TIM1 四路、TIM9 两路、TIM10、TIM11 各一路，10 kHz；编码器：TIM2–5 正交模式，16 位定时器以差值累加为 i32。
- embassy 任务：串口接收与解析、100 Hz 控制循环、20 Hz 遥测、统一发送队列。
- 开机状态：PWM 全零，蜂鸣器静音，LED 闪烁表示运行。

### 6.3 Python（Mac 与 Jetson 通用）

- `robot/car_link.py`：CRC-8、帧编码/解析、`CarLink`（基于 pyserial，打开前将 DTR/RTS 置低；发送命令、读取应答与遥测）。
- `app/car_teleop.py`：键盘遥控，WASD 平移、QE 旋转、空格停车；按键期间 20 Hz 发送 `V`；显示遥测；`--motor N` 单电机标定模式。
- `pyproject.toml` 新增可选依赖组 `car = ["pyserial>=3.5"]`。

## 7. 测试

- 共享测试向量：`firmware/car-core/tests/vectors.txt`（帧文本与期望解析结果、CRC 值），Rust 与 Python 测试均读取同一文件。
- Rust 单元测试：CRC、帧解析的正常与异常（校验错误、超长、缺字段、越界、未知命令、前导噪声重同步）、运动学（纯平移、纯旋转、组合超限等比缩放、占空上限）、`MotionState`（看门狗超时、心跳不刷新看门狗、斜率限制、停止立即归零、单电机模式）。
- Python 单元测试：同一向量；`CarLink` 用串口替身测试 DTR/RTS 置低、应答匹配序号、遥测解析。
- 架空与落地测试按第 1 节成功标准执行，结果写入固件 README。
