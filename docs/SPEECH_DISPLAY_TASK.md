# 语音与展示负责人任务边界

## 1. 任务定位

本任务负责完整实现教学机器人中的交互链路：

```text
学生语音输入 -> 录音 -> 语音识别 -> 核心教学处理 -> 回答文本
    -> 语音合成 -> 音频播放
    -> 页面展示任务、观察、教学阶段、动作状态和交互过程
```

最终目标是：学生能够通过语音输入，系统能够播报回答，页面能够展示过程并发出停止请求。

本文件定义任务范围和职责边界；截至 2026-10-07 的实现进度见第 10 节。实现进度不代表接口合同已批准。

## 2. 负责目录

主要实现范围如下：

| 目录 | 职责 |
| --- | --- |
| `providers/` | 录音、ASR、TTS、播放等外部服务或设备适配器 |
| `speech/` | 语音录制、识别、合成、播放的业务编排与资源生命周期 |
| `frontend/` | 任务交互、状态展示、媒体展示、录音入口和停止操作 |
| `tests/` | 语音服务、播放取消、页面接口和错误场景测试 |

必要的集成改动可以在现有核心门面和已定义接口范围内完成，但不得借此重写核心 Runtime、教学决策或机器人设备层。

## 3. 语音输入职责

### 3.1 录音服务

- 支持按键开始录音。
- 支持按键结束录音。
- 配置麦克风、采样率、声道和最长录音时长。
- 到达最长时长后自动结束或进入可识别状态。
- 返回登记后的音频引用和录音编号。
- 正确处理无录音设备、设备占用、空录音、录音失败和取消。
- 录音结束与自动结束并发发生时不得保存或识别两次。
- 关闭服务时释放麦克风和相关任务。

### 3.2 语音识别客户端

- 接收录音服务产生的音频引用或音频内容。
- 调用配置的识别服务，或使用模拟识别实现测试链路。
- 返回最终文本、识别状态和可读错误。
- 只接受最终识别结果作为教学输入。
- 空文本不提交为学生输入。
- 同一录音只能提交一次识别，重复请求返回已有状态或明确拒绝。
- 识别超时、服务失败、响应格式错误和任务取消必须有明确结果。
- 迟到的识别结果不得重新激活已取消或已结束的任务。

## 4. 语音输出职责

### 4.1 语音合成客户端

- 输入非空回答文本，返回音频引用。
- 支持配置音色、服务地址、请求超时和相关模型参数。
- 支持模拟音频，用于本地开发和自动化测试。
- 正确处理文本过长、超时、服务不可用、响应错误和合成失败。
- 合成完成只表示音频已经生成，不表示用户已经听到回答。
- 取消合成后，迟到的音频不得自动播放。
- 关闭服务时清理未完成的合成任务和临时资源。

### 4.2 播放服务

- 播放合成完成的音频。
- 提供实际播放中的状态和播放完成反馈。
- 区分 `playing`、`completed`、`stopped` 和 `failed`。
- 支持播放期间中途停止，并等待确认停止。
- 取消播放后清理播放器资源，不报告为正常播完。
- 播放服务关闭时停止活动播放并释放音频设备。
- 播放完成与合成完成必须分别记录，不能用合成状态代替播放状态。
- 播报期间按照现有模块合同处理录音互斥和设备占用。

## 5. 展示页面职责

页面独立放在 `frontend/`，负责面向学生或操作者呈现交互状态：

- 输入或选择任务。
- 显示系统回答和语音输出状态。
- 展示摄像头图片、观察结果和观察错误。
- 展示当前教学阶段。
- 展示动作排队、执行、验证、成功、失败、取消和超时状态。
- 提供开始录音和结束录音入口。
- 提供停止当前任务或停止当前播报的操作。
- 根据核心提供的事件接口刷新页面状态。
- 处理页面断线、请求失败、事件重连和服务不可用，并给出明确提示。
- 第一版先使用模拟数据验证页面流程，再接入真实接口。

页面不直接调用 VLM、ASR 或 TTS 服务，不保存服务凭据，不访问后端文件路径。

## 6. 交付顺序

按以下顺序逐阶段交付，每阶段完成验证后再开始下一阶段：

### 阶段一：语音输入版本

完成录音服务、模拟或真实 ASR 客户端、录音到文本的核心连接，以及无语音、识别失败、重复提交和取消测试。

验收条件：完成一次录音后能够得到最终文本；空录音不会提交学生输入；同一录音不会重复识别。

### 阶段二：语音输出版本

完成 TTS 客户端、模拟音频、播放服务、播放状态和停止清理。

验收条件：输入文字能够生成并播放音频；能够区分合成完成和播放完成；播放期间可以停止；合成或播放取消后不会继续播报。

### 阶段三：页面版本

先使用模拟任务、观察、动作和事件数据完成页面流程，再连接现有真实接口。

验收条件：页面能够展示任务、回答、图片、观察、教学阶段和动作状态；能够发起录音和停止请求；断线和请求失败时有明确提示。

### 阶段四：最终交互验收

验证完整链路：

1. 学生开始并结束录音。
2. 系统取得最终识别文本。
3. 核心处理该输入并产生回答。
4. 系统合成并实际播放回答。
5. 页面持续显示观察、教学阶段和动作状态。
6. 学生或操作者发出停止请求后，相关播放或任务得到明确停止结果。

## 7. 接口与协作约束

- 共享模型优先使用 `domain/services.py` 中已有的数据契约。
- 感知接口使用 `perception/interfaces.py` 中已有的 Protocol 和模型。
- 语音接口使用 `speech/interfaces.py` 中已有的 Protocol 和模型。
- 证据通过 `storage/evidence.py` 管理，不能向前端暴露本地绝对路径。
- 核心任务和输入通过 `app/team_gateway.py` 以及已审核的模块合同衔接。
- Runtime 的事件队列是单消费者模型，页面不能直接竞争读取；需要由核心广播器分发事件。
- HTTP 路径、请求、响应和错误码以 `API_CONTRACT.md` 为准。
- 新增、删除或修改 HTTP 接口前，必须先更新接口合同并交由项目负责人审核。
- 依赖通过构造函数注入，模块导入时不得连接设备、启动任务或修改全局代理。
- 凭据、服务地址和设备配置使用环境变量或显式配置，不写入源码。
- 异步设备和服务调用必须正确响应协程取消，不能把取消伪装成成功。
- 日志不得输出凭据、完整音频、完整模型请求或本地敏感路径。

## 8. 必须覆盖的测试

至少覆盖以下行为：

- 没有麦克风设备。
- 空录音。
- 录音失败和录音取消。
- ASR 服务失败、超时和非法响应。
- 同一录音重复提交。
- TTS 合成失败、超时和非法响应。
- 合成期间取消，取消后不得自动播放。
- 播放期间取消，必须确认停止并释放资源。
- 播放自然完成与中途停止的状态区别。
- 服务关闭后麦克风、播放器和后台任务均被释放。
- 页面断线、事件重连和请求失败。
- 页面停止按钮能够发出正确的停止请求。
- 已取消或已结束任务收到迟到识别结果时不会恢复任务。

## 9. 明确不负责的事项

本任务不负责以下工作：

- 重新设计或实现 `runtime/` 动作执行器。
- 修改机器人设备适配器和真实机器人运动协议。
- 实现教学 Agent、教学决策模型或教学阶段推进逻辑。
- 猜测或确定尚未提供的真实 VLM、ASR、TTS 服务协议。
- 默认接入云端模型、创建密钥或提交真实部署地址。
- 将模拟设备或模拟服务标记为真实能力。
- 在接口合同未经审核时自行新增或修改 HTTP 端点。
- 将页面直接连接到 VLM、ASR、TTS 或后端本地文件。
- 同时启动多个未完成的交付阶段。
